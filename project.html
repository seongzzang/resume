이미지 캐싱 처리 문제
문제 인식
기사 지면 이미지를 열 때마다 네트워크 재요청이 발생하고 메모리 사용량이 증가하는 문제가 있었습니다. 같은 이미지를 다시 볼 때도 로딩이 반복되어 열람 흐름이 끊기고, 이미지가 많은 화면에서는 메모리 부담이 커졌습니다.
문제 해결
NSCache 기반의 이미지 메모리 캐시를 구현하여 이미 불러온 이미지는 재요청 없이 바로 사용하도록 개선했습니다. 캐시 용량과 개수 제한을 설정해 메모리 사용량을 제어했고, 메모리 경고 시 시스템이 캐시를 자동으로 해제하도록 처리했습니다. 그 결과 이미지 메모리 사용량을 21% 줄이고, 이미지 재방문 시 로딩 속도를 개선했습니다. 이 과정을 통해 이미지 캐싱 전략과 메모리 관리의 중요성을 이해하게 되었고, 이후 이미지가 많은 화면에서도 성능 문제를 더 빠르게 파악하고 개선할 수 있는 역량을 갖추게 되었습니다.
특정 기사 PATH 문제
문제 인식
신문 지면에서 특정 기사를 선택했을 때 해당 기사 영역(Path)의 범위를 정확하게 잡는 데 어려움이 있었습니다. 특히 지면 이미지를 확대·축소하면 화면에 표시되는 이미지 크기와 위치가 계속 달라져, 서버에서 받은 기사 범위가 실제 기사 위치와 어긋나는 문제가 발생했습니다.
문제 해결
서버에서 받은 기사 범위 값과 SwiftUI가 이미지를 화면에 배치하면서 자동으로 계산하는 이미지 표시 범위를 코드로 맞춰, 확대·축소 상태에서도 선택한 기사의 Path가 정확하게 잡히도록 구현했습니다. 이와 함께 열람 화면의 다른 UI 편의성도 개선하여 사용자 수를 11% 증가시키는 성과를 얻었습니다. 이 과정을 통해 이미지 좌표계와 화면 좌표계의 차이를 이해하게 되었고, 이후 확대·축소나 레이아웃 변화가 있는 화면에서도 좌표 문제를 더 빠르게 파악하고 해결할 수 있는 역량을 갖추게 되었습니다.
