Image Caching Issue
Problem Identification
Every time a newspaper page image was opened, a new network request was sent and memory usage increased. Even when revisiting the same image, it had to load again, interrupting the reading flow, and screens with many images put heavy pressure on memory.
Problem Solution
I implemented an NSCache-based in-memory image cache so that already-loaded images are reused immediately without new requests. I set limits on cache size and item count to control memory usage, and let the system purge the cache automatically on memory warnings. As a result, image memory usage dropped by 21% and loading became faster when revisiting images. Through this process, I came to understand the importance of image caching strategies and memory management, and gained the ability to identify and fix performance issues more quickly on image-heavy screens.
Article Path Issue
Problem Identification
When a user selected an article on a newspaper page, it was difficult to accurately define the article's area (path). In particular, zooming in and out of the page image constantly changed the displayed image's size and position, so the article bounds received from the server no longer matched the article's actual position.
Problem Solution
I aligned the article bounds from the server with the image display area that SwiftUI calculates automatically when laying out the image, so the selected article's path is accurately drawn even while zoomed in or out. Along with other usability improvements to the viewer screen, this led to an 11% increase in users. Through this process, I came to understand the difference between image and screen coordinate systems, and gained the ability to identify and resolve coordinate issues more quickly on screens with zooming or layout changes.
