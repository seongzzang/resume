문제 인식
앱 실행 후 첫 화면에서 지면 이미지와 관련 데이터를 한꺼번에 불러오는 구조여서, 불러올 데이터가 많은 사용자일수록 초기 로딩이 길어지는 문제가 있었습니다. 사용자는 빈 화면이나 로딩 상태를 오래 기다려야 했고, 이에 따른 문의도 늘어나는 영향을 주었습니다.
문제 해결
이미지와 기사를 초반에 많이 가져와야 하는 사용자의 경우를 위해 데이터를 불러오는 시점을 앱 시작 단계에서 각 화면이 실제로 필요한 시점으로 옮기고, async/await 기반 비동기 처리를 적용하여 이미지와 데이터 요청이 UI를 막지 않도록 개선했습니다. 대기 시간을 조절을 통해 로딩 중에도 사용 흐름이 끊기지 않도록 했고, 그 결과 로딩 지연과 관련된 사용자 문의가 달에 5건이던 문의가 거의 없어졌습니다. 이 과정을 통해 데이터 호출 시점 설계와 비동기 이미지 처리가 앱 체감 성능에 미치는 영향을 이해하게 되었고, 이후 데이터가 많은 화면에서도 로딩 구조를 먼저 점검하고 개선하는 역량을 갖추게 되었습니다.
팀원 간 코드 스타일·Git 협업 방식 차이 조율
문제 인식
안드로이드 개발 경험을 가진 팀원이 iOS 프로젝트에 합류하면서 MVVM 구조와 코드 스타일에 차이가 발생했습니다. 또한 GitLab 사용 경험이 없어 브랜치를 나누지 않고 작업하다 보니 코드 충돌이 자주 발생했고, 이로 인해 작업 흐름과 협업 효율이 떨어지는 문제가 있었습니다.
문제 해결
MVVM 구조에 맞게 폴더 구조를 함께 정리하고, 코드를 서로 공유하며 충분한 대화를 통해 코드 형식을 맞춰 회사의 코드 스타일을 팀 전체가 익힐 수 있도록 했습니다. Git 협업은 브랜치를 기능 단위로 나누어 작업하는 방식을 논의하고 직접 테스트해 보며 팀에 맞는 방식으로 조율했고, 그 결과 코드 충돌을 줄이고 병렬 작업이 가능한 흐름을 만들었습니다. 이 과정을 통해 다른 플랫폼 경험을 가진 동료와 일하는 방법과 브랜치 전략의 중요성을 이해하게 되었고, 이후 새로운 팀원이 합류하는 환경에서도 코드 규칙과 협업 방식을 빠르게 정립해 가는 역량을 갖추게 되었습니다.
